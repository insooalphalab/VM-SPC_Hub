# VM-Hub — 역할 분할 설계

기존 VM-SPC Core 한 곳에 몰려 있던 수집 · 검증 · 판단 · 화면 · 뉴스를 역할 5개로 나눈다.
데이터를 모으는 네 역할이 정리본을 내면, 코어가 검증된 규칙으로 판단해 사용자에게 리포트 한 편으로 보낸다.

```
2 국내 시장 ─┐
3 해외 시장 ─┤   exchange/{역할}/{날짜}/summary.json · summary.md
4 매크로   ─┤ ──────────────────────────────────────────────▶  1 코어: 판단(검증된 규칙만) → 리포트(페이지 + 텔레그램)
5 뉴스     ─┘                                                    새 지표 · 아이디어 → VM-SPC_Core 세션에 검증 요청 → 등급
```

문서 읽는 순서: 이 파일(설계 · 데이터 지도) → `CLAUDE.md`(공통 작업 지침 · 예약) → `exchange\README.md`(주고받는 형식) → 각 역할 `README.md`(파일 지도) · `CLAUDE.md`(그 역할의 규칙 · 결정).

## 폴더 한눈에

```
VM-Hub/
  README.md · CLAUDE.md        설계 · 공통 지침
  1_core/                      판단 · 리포트 · 텔레그램 전송        README · CLAUDE
  2_kr_market/                 국내 시장 정리본(Core 결과 읽기 + KIS 일부)
  3_us_market/                 미국 정리본(VM-SPC_Global 결과 읽기)
  4_macro/                     매크로 수집 · 체크리스트 · 모니터(원자료는 여기에만)
  5_news/                      텔레그램 수집(유일) · 뉴스 요약
  exchange/                    역할 간 정리본(형식 문서만 커밋)
  scripts/                     예약 스크립트: hub_am · hub_pm · hub_month(.ps1 + 숨김 .vbs) · register_tasks.ps1
  logs/                        예약 실행 로그(git 제외)
```

각 역할 폴더는 같은 모양이다: 맨 위에 그 역할 코드(`export_exchange.py`가 정리본을 내는 본체), `core\` · `vm_spc\` · `reports\` · `dart_events\` = 원본(VM-SPC_Core · Global · KIS_auto)에서 같은 구조로 복사한 코드, `data\` · `results\` · `state\` = 자동 생성물(git 제외), `.streamlit\secrets.toml` · `.env` = 그 역할에 필요한 키만(비밀).

**파일을 옮기지 않는다.** 예약 스크립트 · 역할끼리 · VM-SPC_Core 검증 스크립트가 경로를 직접 적어 읽는다. 무엇이 어디서 읽히는지는 각 역할 `README.md` "옮기지 말 것" 표.
